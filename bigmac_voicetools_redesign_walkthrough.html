Optimized walkthrough: the rebuilt product flow

Open to a creator promise, not a server report

“Build a local audio-drama scene” becomes the first sentence. Health appears as capability: Can parse, can render, can assemble. Ports go to diagnostics.

Start with safety and voice readiness

Before uploads, show local-only scope, consent acknowledgement, and sample quality requirements. Voice cards show readiness, not just names.

Create or resume a project workspace

Project is the root object: voices, characters, scenes, takes, previews. The workspace remembers active project, scene, and step.

Parse script into visible scene units

Replace raw JSON with scene cards, speaker count, warnings, and save state. Multi-scene imports must never silently collapse into scene zero.

Bind speakers with explicit blockers

Every speaker row says Ready, Needs character, Needs voice, or Unknown. Each blocker has one next action.

Render through a queue users can trust

Render-ready means ready lines only. Show queued/current/done/failed/canceled. No hidden all-line payloads. No console-only errors.

Review takes as a production task

Selected take state is scene-level, not buried. The app shows how many lines have canonical takes and which still need review.

Preview only when readiness is legible

Build preview shows missing selections before failure. Player visibility is deterministic. Export/open/copy actions activate only after real output exists.

Reasoning

The product’s real endpoint is assembled audio, so the UI should expose continuity, timing, line order, speaker tracks, and selected takes. This borrows the mental model of audio editors without becoming a full digital audio workstation.

Tradeoff

Excellent for power users and long scenes. Too much for a first-run user unless paired with Solution 5 as beginner mode.

Implementation walkthrough

  1. Render scene lines as timeline clips grouped by speaker.
  2. Represent selected take as the clip body; missing take as dashed placeholder.
  3. Expose line-level timing directly on clips.
  4. Move take audition into right inspector.
  5. Preview readiness scans timeline gaps, not hidden state.

What to steal

Resemble Chatterbox explicitly frames short-reference voice cloning, emotion control, watermarking/security, and on-prem deployment. This app should turn those ideas into local trust UI and sample readiness.

Implementation walkthrough

  4. Add voice readiness badges: Ready, Risky, Missing consent, Missing file.
  5. Expose character usage: which scenes/roles depend on each voice.

Corrected bug this targets

handleRenderReadyLines() computes ready lines but sends all line IDs. This redesign makes the requested set visible and inspectable before execution.

Implementation walkthrough

  1. Change payload to ready line IDs only.
  2. Create renderQueueState: queued/current/done/skipped/failed/canceled.
  3. Show human line labels: speaker + excerpt, not raw line IDs.
  4. Add cancellation semantics or “stop after current line.”
  5. Replace native confirm with custom scoped destructive modal.
Solution 5

Focus Composer

A beginner-safe interface that hides almost everything until it is needed. One task. One decision. One next button. Advanced controls remain available, but not dumped in the user’s lap like a box of cursed knobs.

CalmBest as first-run mode.

Plain-English rule: The app will not ask about ports, tunnels, seeds, CFG, or remote paths unless you open Advanced or Diagnostics.

Reasoning

The current UI assumes the user understands the whole stack. Focus Composer assumes nothing, which is correct. The system knows enough to guide the user through the first successful preview.

Tradeoff

This is not enough for advanced production by itself. It should coexist with Pro Studio, not replace it.

Implementation walkthrough

  1. Add mode switch: Focus / Pro.
  2. Focus mode routes through Create Voice → Paste Script → Bind Missing Speakers → Render → Preview.
  3. Hide technical controls unless a step fails or Advanced is opened.
  4. Convert errors into plain actions: “Add a voice for UNKNOWN” rather than “MISSING_VOICE.”
  5. Offer “Show technical details” after every failure.
